# Git — what it does for you, and the four commands you need

Git is installed and this folder is now a repository. Your work is already
protected: every version is saved, and any bad edit can be undone.

---

## The one command that saves you

Broke something and want the last saved version back?

```
git checkout -- V2-PORTFOLIO.html
```

That is it. The file returns exactly as it was at the last commit. This
has been tested — the file was deliberately destroyed and came back whole.

To throw away ALL changes since the last save:

```
git checkout -- .
```

---

## Saving your work

After a change you are happy with, run these two:

```
git add -A
git commit -m "what you changed"
```

Write the message for your future self: "made the About cards draggable
on phones" tells you something six months from now. "update" does not.

To see what you have changed since the last save:

```
git status
```

To see the history:

```
git log --oneline
```

## Putting it on GitHub

Everything above works offline, on this computer only. GitHub puts a copy
online — so the work survives if this laptop does not, and Netlify can
deploy from it automatically.

**1. Make an account** at https://github.com — free, no card.

**2. Make a repository.** Click **+** (top right) → **New repository**.

- Name: `velvet-theory`
- **Private** unless you want the code public
- Do **NOT** tick "Add a README", ".gitignore" or a licence — this folder
  already has its own history, and those would collide with it

**3. Push it up.** GitHub will show you a page of commands. Ignore most of
it and run these three, with YOUR username in place of `YOURNAME`:

```
git remote add origin https://github.com/YOURNAME/velvet-theory.git
git branch -M main
git push -u origin main
```

A browser window will open to sign in. That is normal — it happens once.

**After that**, every time you want to send your saved work up:

```
git push
```

## Deploying from GitHub instead of dragging folders

Once the code is on GitHub, Netlify can watch it and rebuild whenever you
push. But note: this site has **no build step** — `publish.ps1` runs on
your computer, not on Netlify's servers. So either:

- **Keep dragging `PUBLISH/`** onto Netlify after running `publish.ps1`.
  Simple, and it already works.
- **Or** commit the `PUBLISH/` folder too (remove that line from
  `.gitignore`) and point Netlify at it as the publish directory. Then a
  `git push` deploys the site. It costs some repository size, because the
  photographs are then stored twice.

The first is fine. Only bother with the second if dragging folders starts
to annoy you.

## What is NOT in the repository, and why

The folder on disk is 402 MB. The repository is 39 MB. `.gitignore`
excludes:

- `PUBLISH/` — generated by `publish.ps1` from files that ARE tracked
- `*.zip` — snapshots; committing them would double the size each time
- `NEW IMAGES/`, `photos for website/`, `cover photos/`, `random stuff/`,
  `traditional potraits/` — camera originals the site does not use
- `V1-*.html`, `*-SAMPLE.html`, `*-STUDY.html`, `PARKED-*.txt`, `*.bak` —
  old experiments, still on disk, just not in the history

Those files are all still on your computer. They are simply not tracked.

**Note that these are excluded from GitHub but exist nowhere else.** If
the camera originals matter to you, copy them to Google Drive or a USB
drive separately — Git is not backing them up.

## If a command fails

- **"git is not recognised"** — close the terminal and open a new one.
  Git was just installed and the old window does not know about it yet.
- **"fatal: not a git repository"** — you are in the wrong folder. Run
  `cd "C:\Users\Sai veekshith\OneDrive\Desktop\CLOUDE"` first.
- **"remote origin already exists"** — you ran the `remote add` line twice.
  Use `git remote set-url origin <the url>` instead.
- **Asked for a password and yours does not work** — GitHub stopped
  accepting account passwords for this. The sign-in window that opens in
  your browser is the way in; use that rather than typing a password.
